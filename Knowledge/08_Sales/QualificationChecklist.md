# Client & Project Qualification Checklist

## Purpose

Before investing time in writing a proposal, evaluate whether the opportunity is worth pursuing.

Not every project is worth applying for.

The objective is to maximize interview rate, hire rate, return on time invested, and long-term client value.

---

# Overall Evaluation

For every opportunity, determine:

* Is this a real project?
* Is the client serious?
* Am I technically capable?
* Can I realistically deliver?
* Is the budget reasonable?
* Is this the type of work I want?
* Does this project help grow my portfolio?
* Is there potential for long-term collaboration?

---

# Technical Fit

Evaluate:

* Technology stack
* Project complexity
* Domain knowledge
* Required integrations
* Performance requirements
* Security requirements
* AI requirements
* Healthcare requirements
* Cloud requirements
* Third-party services

Classify:

Excellent Fit

Good Fit

Partial Fit

Poor Fit

---

# Business Fit

Determine:

* Does the project align with my services?
* Does it align with my long-term goals?
* Can it become a recurring client?
* Will it generate a strong portfolio case study?
* Is it likely to lead to referrals?

---

# Budget Evaluation

Determine whether:

* Budget matches project complexity.
* Client understands development costs.
* Fixed-price scope is realistic.
* Hourly expectations are reasonable.

Watch for:

* Extremely low budgets
* Enterprise expectations with tiny budgets
* "Quick task" descriptions hiding large projects

---

# Client Quality

Evaluate:

Payment verification

Past hiring history

Reviews from freelancers

Interview rate

Average project value

Communication quality

Response time

Long-term hiring history

Repeat hiring behavior

---

# Job Description Quality

A good job description usually includes:

* Clear objectives
* Functional requirements
* Expected deliverables
* Preferred technologies
* Timeline
* Budget
* Communication expectations

Poor descriptions often indicate unclear scope.

---

# Scope Risk

Look for warning signs:

* Constantly changing requirements
* "Everything" projects
* Undefined scope
* Missing specifications
* Unrealistic deadlines
* Fixed budget with unlimited revisions

---

# Red Flags

Examples:

* "Need this today."
* "Very easy task."
* "Lowest bid wins."
* "Must work weekends."
* "Unlimited revisions."
* "Budget will increase later."
* "Need entire team."
* "Payment after completion."
* "We have many more projects if this works."

These do not automatically disqualify the project, but they should increase caution.

---

# Positive Signals

Examples:

* Detailed requirements
* Realistic budget
* Payment verified
* Previous successful hires
* Technical understanding
* Respectful communication
* Clear success criteria
* Long-term roadmap

---

# Questions Before Applying

Can I confidently complete this project?

Can I deliver high-quality work?

Will this strengthen my portfolio?

Will I enjoy working on this?

Would I accept this project if it were offered today?

If the answer to several of these is "No," reconsider applying.

# Decision

Choose one:

* Apply Immediately
* Apply with Clarification
* Save for Later
* Do Not Apply

Document the primary reasons for the decision.

---

# Continuous Improvement

Review hiring outcomes regularly.

Identify patterns such as:

* Which industries respond most often.
* Which budgets produce the best clients.
* Which project sizes lead to repeat work.
* Which marketplaces produce the highest-quality opportunities.

Use these insights to improve future qualification decisions.
