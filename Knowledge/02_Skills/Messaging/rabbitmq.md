# RabbitMQ

## Overview

RabbitMQ is my primary message broker for building reliable, scalable, and loosely coupled distributed systems. I use RabbitMQ to enable asynchronous communication between services, process background jobs, improve system resilience, and support event-driven architectures.

I integrate RabbitMQ with .NET, ASP.NET Core, Node.js, NestJS, and microservices-based applications to ensure reliable message delivery, improve application responsiveness, and decouple business processes.

# Best Practices

* Keep messages small and focused.
* Design consumers to be idempotent.
* Use durable queues for critical workloads.
* Implement retry policies with limits.
* Route failed messages to Dead Letter Queues.
* Monitor queue health and consumer performance.
* Avoid blocking operations inside consumers.
* Design producers and consumers to evolve independently.
* Log failures with sufficient context.
* Document message contracts between services.
