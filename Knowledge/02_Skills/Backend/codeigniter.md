# CodeIgniter

## Overview

CodeIgniter is one of my backend frameworks for building lightweight, fast, and straightforward web applications and APIs using PHP. I use CodeIgniter for custom backend development, internal tools, legacy system maintenance, and projects where a small footprint and simplicity are priorities.

While I often choose Laravel for larger, feature-rich applications, CodeIgniter remains an excellent choice for lightweight services, legacy application support, and projects requiring minimal overhead.

# Best Practices

* Keep controllers lightweight and delegate logic to models/libraries.
* Use Query Builder to prevent SQL injection.
* Validate all form and API input.
* Apply filters for cross-cutting concerns like authentication.
* Structure code for maintainability despite the framework's minimal conventions.

# Comparison with Laravel

Choose CodeIgniter when

* Maintaining or extending an existing CodeIgniter application.
* A minimal-footprint framework is preferred.
* The project is small in scope with simple requirements.

Choose Laravel when

* Building a new application from scratch.
* The project will grow in complexity over time.
* Built-in tooling (queues, Eloquent, Sanctum) provides long-term advantages.

# Notes for AI

CodeIgniter should be highlighted when clients specifically use or require CodeIgniter, particularly for legacy application maintenance or lightweight PHP projects.
