# Frontend Development Service

## Service Summary

I build responsive, maintainable user interfaces that consume real APIs and hold up under real users — not static mockups. Whether it's a customer-facing product, an internal admin tool, or a complex data-heavy dashboard, I focus on interfaces that are fast, accessible, and easy for other developers to extend later.

I work across React, Angular, and Vue, choosing the framework based on the client's existing codebase or the complexity of the application rather than personal preference.

---

# Service Overview

This service includes:

* Single Page Application (SPA) Development
* Component Architecture & Design Systems
* State Management
* API Integration
* Responsive & Mobile-Friendly Design
* Form Handling & Validation
* Authentication-Aware UI (protected routes, role-based views)
* Performance Optimization
* Accessibility Improvements

# Business Problems Solved

Clients typically hire me to:

* Build a new frontend for a product or MVP
* Rebuild an outdated or unmaintainable frontend
* Add new features to an existing React/Angular/Vue application
* Connect an existing frontend to a new or changed backend API
* Improve performance or loading times
* Make an application properly responsive across devices

# Best Practices

* Component-driven architecture for reusability
* Strict typing with TypeScript to reduce runtime bugs
* Clear separation between presentation and data-fetching logic
* Responsive-first design
* Consistent state management pattern per project
* Performance budgets (lazy loading, code splitting)

---

# Common Client Problems Solved

* Frontend is hard to extend because of inconsistent component structure
* Application doesn't work well on mobile devices
* Slow load times affecting user experience or conversions
* No clear state management strategy leading to bugs
* Frontend and backend are out of sync after API changes

# Discovery Questions

When appropriate, ask:

* Is there an existing frontend, or is this a new build?
* Which framework does the client's team already use, if any?
* Are there existing design files (Figma, etc.) to work from?
* Who are the end users, and what devices do they primarily use?
* Are there specific performance or accessibility requirements?

# Notes for AI

Frontend Development should be paired with Backend Development or REST API Development when a client needs a complete application rather than just UI work. Match the recommended framework to the client's existing stack when known; default to React for new greenfield SPAs and Angular for large enterprise dashboards unless the client states a preference.
