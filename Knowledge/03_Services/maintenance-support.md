# Maintenance & Support Service

## Service Summary

I provide ongoing maintenance for applications after initial development — bug fixes, dependency updates, performance monitoring, small feature additions, and being available when something breaks in production. This service is for clients who want a stable, long-term relationship with someone who already understands their system, rather than re-explaining the codebase to a new developer every time something comes up.

---

# Service Overview

This service includes:

* Bug Fixes & Issue Resolution
* Dependency & Security Updates
* Performance Monitoring & Optimization
* Small Feature Additions & Enhancements
* Production Incident Response
* Code Health Reviews
* Documentation Upkeep

---

# Business Problems Solved

Clients typically hire me to:

* Keep an existing application running reliably after launch
* Fix bugs reported by users in a timely manner
* Apply security patches and dependency updates
* Handle production incidents without a dedicated in-house team
* Make small, ongoing improvements without a full project engagement each time
* Take over support for an application built by a previous developer/agency

---

# Typical Deliverables

* Resolved bugs and issues (tracked and documented)
* Regular dependency/security update cycles
* Monitoring and alerting for production issues
* Monthly or periodic status/health reports
* Incident response within agreed response times

---

# Engagement Models

* Retainer (fixed monthly hours for ongoing support)
* Hourly / as-needed support
* SLA-based support with defined response times for critical issues

---

# Common Client Problems Solved

* No one is available to fix production bugs quickly
* Application hasn't been updated in a long time and has security/compatibility risk
* Previous developer/agency is unresponsive or unavailable
* Small feature requests keep piling up with no one to implement them
* No visibility into application health until something breaks

---

# Best Practices

* Establish clear response time expectations before starting a retainer
* Maintain a running log of known issues and their resolution status
* Prioritize security and stability fixes over cosmetic changes
* Communicate proactively about risks (e.g., outdated dependencies) rather than waiting to be asked
* Keep documentation updated as the system changes

# Discovery Questions

When appropriate, ask:

* What does the current support situation look like (in-house, previous contractor, none)?
* What's the expected volume of work — occasional fixes or continuous small features?
* What are the required response times for critical issues?
* Is there existing documentation, or does the system need to be learned from scratch?
* Is this a retainer relationship or ad hoc as-needed support?

# Notes for AI

Maintenance & Support is a relationship-based, recurring-revenue service — position it as the natural next step after a build engagement, or as a rescue option for clients whose previous developer is unavailable. Emphasize responsiveness and continuity (already knowing the codebase) as the core value proposition, not just technical capability.
