# Scope Checklist

## Purpose

A defined scope is what makes any price — fixed or hourly-with-a-cap — safe to commit to. This checklist should be worked through before finalizing any estimate.

---

# Functional Scope

* [ ] What are the specific features/user stories included?
* [ ] What is explicitly *not* included (out of scope)?
* [ ] How many user roles/permission levels are there?
* [ ] What are the core user workflows, end to end?

---

# Technical Scope

* [ ] Is this a new build or work on an existing codebase?
* [ ] What third-party integrations are required?
* [ ] Are there AI requirements? (see `Knowledge/03_Services/ai-integration.md`)
* [ ] What authentication method(s) are required?
* [ ] Are there notification requirements (email, SMS, push)?
* [ ] Are there reporting/analytics requirements?
* [ ] What are the deployment requirements — new infrastructure or existing?
* [ ] Is ongoing maintenance included, or a separate engagement?

---

# Data & Compliance Scope

* [ ] Is there existing data to migrate?
* [ ] Are there compliance requirements (HIPAA, GDPR, etc.)?
* [ ] Are there specific security requirements beyond standard practice?

---

# Design Scope

* [ ] Are designs/wireframes provided, or does design work need to be estimated separately?
* [ ] How many distinct screens/views are involved?
* [ ] Is responsive/mobile design required?

---

# Delivery Scope

* [ ] What counts as "done" for each milestone?
* [ ] How many revision rounds are included per milestone?
* [ ] Who provides content, copy, and assets — client or freelancer?
* [ ] What's the expected timeline, and is it realistic given the scope?

---

# Red Flags to Resolve Before Quoting

* Vague requirements ("build me something like X")
* "Unlimited revisions" expectations
* Scope described as "small" without supporting detail
* Client unsure of their own requirements — recommend a paid discovery phase instead of guessing

# Guiding Principle

If a checklist item can't be answered confidently, the scope isn't ready for a fixed quote yet — resolve it first.
